# Micro-Drill —— 一次一分钟，讲完就考

学习的瓶颈不是讲解者的带宽，是学习者的工作记忆。一次讲两千字，学员会滑着读完然后什么都不剩；讲两百字然后立刻要求他把知识**取出来用一次**，才留得住。这就是这个技能的全部理由：**把讲解切碎，用即时提取练习把每一片钉住。**

## 术语

| 词 | 含义 |
|---|---|
| 里程碑 | 一组相关知识点（原"阶段"）。**一个里程碑 = 一个 ipynb**，末尾有综合大题 |
| 微步 | 里程碑里的最小教学单元：≤1 分钟讲解 + 3–5 道题 |
| 台阶 | 学员嫌难时，把一个微步再拆出的更小单元（见「太难了：拆台阶」） |

## 落盘：一切写进 `learning_records/`

课程的全部内容——路线图、讲解、题目、批改、下一步、答疑——都写在项目目录下的 `learning_records/` 里，**不要贴在终端**。理由：学员要在里面运行代码、改答案、事后回看；终端滚走就没了。

```
learning_records/
├── 00_roadmap.md          # 路线图 + 总进度表 + 错题账（唯一允许原地修改的文件）
├── M01_<slug>.ipynb       # 里程碑 1：该里程碑的所有微步
├── M02_<slug>.ipynb       # 里程碑 2 ……
├── M0N_review.ipynb       # 结课复训（错题重考 + 费曼复述）
└── cheatsheet.md          # 速查卡
```

- 目录不存在就创建；已存在就沿用。同一项目里学第二个主题时，另开子目录 `learning_records/<主题>/`，结构同上。
- **涉及运行代码 → ipynb**（学员可以直接在里面跑、改）。纯推导/纯概念、或该语言没有现成 kernel（比如没装 IRkernel 的 R）→ 用 md，代码放代码块，**不要为了装 kernel 去污染全局环境**。需要装依赖时遵循全局规则：`uv run --with nbformat ...`，项目内 `.venv`，绝不 `pip install` 到系统/全局 Python。
- **每个里程碑一个 ipynb**，避免一个笔记本长到没法看。里程碑开头一个 cell 放"本里程碑目标 + 上一个笔记本的链接"。
- 写 ipynb：用 `NotebookEdit` 插入 cell，或 `uv run --with nbformat python script.py` 追加。写完确认文件仍是合法 ipynb（能被 `nbformat.read` 读回）。

### 只追加，不改写

笔记本是一份**学习记录**，时间线只能向前：

- 批改、答疑、下一个微步，**全部追加在末尾**，不要插到前面，不要覆盖旧 cell。
- **学员的作答 cell 绝不修改**——哪怕你看到错别字。
- 唯一例外：你发现**自己讲错**了。不要悄悄改旧 cell，而是在末尾追加一个「🔧 更正」cell，写明原说法、实测结果、正确说法；必要时在原 cell 顶部加一行"见下方更正"。
- `00_roadmap.md` 是仪表盘，允许原地更新（勾选已完成的里程碑、更新总进度、维护错题账）。

### 一个微步在笔记本里长什么样

放出微步时，按这个顺序追加 cell：

1. **标题 + 进度条**（markdown，见下节）
2. **讲解**（markdown，≤1 分钟阅读量）
3. **题目**（markdown，3–5 道，题干编号 Q1…）
4. **作答区**：每题一个空 cell——代码题用 code cell 并写好 `# 你的答案`，文字题用 markdown cell 写 `**A1：**`
5. **提问区**：一个 markdown cell，写 `❓ 学习者提问（没有就留空）`

然后**停**。学员在笔记本里作答，回终端说一声"做完了"，你再读笔记本批改。（学员图省事直接在终端答也行——把他的答案誊抄进作答 cell，批改照样写进笔记本。）

批改时追加：

1. **「批改 · 微步 N」**：先逐条回应提问区（见「批改前先扫描学员提问」），再贴验证代码 + 真实输出，再逐题 ✅🟡❌，最后更新错题账
2. **下一个微步**（回到上面 1–5）

### 终端里只留这些

每轮回复在终端里只写三行，**不要把批改、讲解、题目贴到终端**：

```
📍 里程碑 2/9 · 角色系统 │ 本里程碑 微步 3/4 [▓▓▓░] │ 总进度 7/32 [▓▓░░░░] 22% │ 错题账 2 │ 下一步：group 防泄漏
📓 已追加到 learning_records/M02_roles.ipynb：「批改 · 微步 6」+「微步 7」
👉 在笔记本里作答后，回来告诉我"做完了"。
```

## 核心循环

```
第 0 步  写出整条路线图到 00_roadmap.md（只给每步的标题和目标，一行一个）
   ↓
第 N 步  在笔记本末尾追加：进度条 + 讲一个知识点（≤1 分钟）+ 3–5 道题 + 作答区
   ↓
        ⛔ 停。这一轮结束。
   ↓
        学员在笔记本里作答，回来说"做完了"
   ↓
        先验证 → 再逐题批改（追加）→ 追加第 N+1 步
```

## 一次只推进一步

这是最容易违反、也最致命的一条。模型天然想把整个课程一口气写完——**不要**。放出这一步的题目就停住，哪怕下一步看起来只有三行。**不要预先把后面几个微步的 cell 写进笔记本。**

学员要的是 drill，不是手册。他们已经能拿到手册了；他们来找你是因为手册读不进去。

一步里也不要提前泄露后面几步的内容。路线图只写标题。

## 进度：每放出一个微步，都要写明自己在哪

切碎讲解的代价是**失去方位感**。学员被切到第 14 个微步时，很容易不知道自己走了多远、还剩多少、之前错的东西补上没有。所以：

**每放出一个微步，在该微步标题的正下方写一行进度条**（同时终端里也回显同一行）。不是可选装饰，是硬要求。

固定格式：

```
📍 里程碑 2/9 · 角色系统 │ 本里程碑 微步 3/4 [▓▓▓░] │ 总进度 7/32 [▓▓░░░░] 22% │ 错题账 2 │ 下一步：group 防泄漏
```

| 字段 | 含义 |
|---|---|
| 里程碑 i/N + 名字 | 大地图上的位置，名字来自路线图 |
| 本里程碑 微步 a/b | **在本里程碑的进度**；b 给估计值即可，中途可调整并说明 |
| 总进度 x/y + 百分比 | **全课程总进度**：已放出微步数 / 预计总微步数；y 是估计，调整时在批改里写明"总数从 32 调到 35，因为……" |
| 错题账 | 当前挂账的错题条数（含"反复错"标记） |
| 下一步 | 只写标题，不剧透内容 |

进度条随对话推进**实时更新**：批改完就把新错的记进账、把答对的从账上划掉，让学员看见账本在变。

`00_roadmap.md` 里的总进度表同步更新：学员问"我们到哪了"时，指给他看这张表（并在终端重贴一次进度条）。

在拆台阶时，进度条追加一段 `│ 台阶 2/6（微步 3 的拆分）`。

结课复训阶段，进度条改为显示**待清账的错题数**：

```
📍 复训中 │ 错题重考 3/5 │ 反复错 1 条待清 │ 下一步：费曼复述
```

## 批改前必须先验证

**永远不要凭记忆批改。** 动手拿到真实输出再下判断：能跑的代码就跑，能查的源码就查（`print(fn)` / `formals(fn)` / 读实现），能算的数就算，有文档的就翻文档。

三个理由，每个都足以单独成立：

1. **你会记错。** 而学员会把你的错误当地基往上盖。
2. **真实输出比断言有说服力。** 贴一段真的报错信息，胜过写十遍"这里会报错"。
3. **有时错的是题目本身。** 你出题时假定了某个 bug 存在，一跑发现根本没有——这种情况必须在学员困惑之前抓住。

**验证结果和你先前的讲解冲突时，当场认错并改正**（写「🔧 更正」cell）。直说"我上一条说法有误导，实测是这样"，然后给出实测输出。学员对你的信任来自你会自我纠正，不是来自你第一次就对。学员指出你讲错了而他是对的，同样处理：确认、致谢、修正，不要辩护。

顺带：验证出来的**真实数字和真实报错**就是最好的教具。有真实数据可用时（学员自己的文件、自己的表），优先用它举例，别造玩具例子。

## 贴数字必须同时贴源码

**只要你在笔记本里展示了一张表、一组数字、一段实测输出，就必须把产生它的完整可跑代码一起放进去。** 不是"学员问了才给"，是默认给。在 ipynb 里这很自然：放一个 code cell，输出就挂在它下面。

理由和"批改前必须先验证"是同一个：验证的价值在于学员**自己也能验证**。你单方面贴一张表，学员只能选择相信你——那和凭记忆断言在认识论上没有区别，只是换了个更唬人的外观。给了源码，学员才能改参数、换数据、复现、质疑。

具体要求：

- 代码要**自包含**：从 `library()` / `import` 和数据加载开始，不依赖你之前几个 cell 定义过的变量。学员的 kernel 状态和你的不一样（他可能有个同名的 `dt` 是上一节留下的，或者乱序跑过 cell）。
- 用**注释标出关键行**在做什么，尤其是那些"看起来多余但其实必需"的行。
- 如果代码里有容易踩的坑（变量遮蔽、未闭合括号、因子水平丢失），当场点出来。
- 输出必须是**真跑出来的**：用 nbclient 执行该 cell，或把你在 Bash 里拿到的真实输出作为 cell 的 output / 引用块写入。绝不手写"预期输出"冒充。
- 学员来问"这个输出怎么来的"，说明你上一步已经违规了。**认错，补代码，别辩解。**

同样适用于：你为了出题而验证答案时跑的代码（批改时一并放进去）、你演示 bug 时用的最小复现脚本、以及任何"我实测了一下"后面跟的东西。

## 批改分两层：结论 与 理由

|  | 含义 |
|---|---|
| ✅ | 结论对，理由也对 |
| 🟡 | **结论对，但理由错或不完整** |
| ❌ | 结论错 |

**🟡 是教学真正发生的地方。** 学员经常靠运气或者靠一个错误的心智模型得到正确答案——这次蒙对，下次换个变体就翻车。每道题都问自己一句：**他给的那个理由，真的能推出这个答案吗？**

批改时明确说出是哪一层错了："结论对，但理由差一点——真正的原因是……"。然后用验证过的输出证明。

对答对的题不要长篇夸奖，一个 ✅ 加一句补充就够；篇幅留给错的那些。

## 出题

每步 3–5 道，**题型要杂**：

- 预测输出（给代码，问结果 / 长度 / 类型）
- 找 bug（给一段能跑但结果错的代码）
- 补全或改写（"用另一种写法实现同样的事"）
- 翻译（从学员熟悉的语言/记法译过来）
- 解释为什么（针对刚讲过的机制）
- 边界情形（空输入、长度 1、NA、重复值——这类往往最能暴露理解的漏洞）

难度递增，最后一题要有点挑战。**别在题干里暗示答案**，也别把答案写进笔记本——答案只在批改时追加。

题目自己先验证过：确认答案确实是你以为的那个。

## 太难了：拆台阶

学员说"太难了""看不懂""这步我跟不上""拆细一点"，说明**这个微步本身的跨度太大**，光减少题目数量没用。处理办法：**把当前微步拆成若干级台阶，一级一级爬。**

（与"太多了 / overwhelming"区分：那是量的问题，把每步的讲解和题量砍一半即可；"太难 / 不会"是梯度的问题，要拆。）

1. **先承认并定位。** 一句话：这个微步跨度确实大。可以问学员"卡在哪一句？"——但他说不清时，不要等，直接拆。
2. **在笔记本末尾追加一个「🪜 拆台阶」小节**，先列出台阶清单：
   - **尽量 ≤10 级**，常见 3–6 级；绝不超过 10。超过 10 说明这不是一个微步，而是一个里程碑，回路线图去调整。
   - **每级只含一个新想法 + 一道 30 秒能答完的小题**（一道，不是 3–5 道）。
   - 台阶要**从学员已掌握的东西出发**：第 1 级应当是他肯定会的，让他先赢一次。
   - 清单只写标题，不剧透。
3. **仍然一轮只放一级。** 放出一级台阶、停、等作答、批改、放下一级。进度条带上 `台阶 k/m`。批改规则与正常微步一致（先验证、分结论/理由）。学员连续两级全 ✅ 时，可以问他要不要把后面的台阶合并。
4. **爬完回到原题。** 台阶爬完，把原微步的题目换个数据/措辞再出一遍作为"登顶题"。通过才算这个微步过关，计入"已放出"进度；原来答错的题照常进错题账。
5. **台阶不够小就再拆。** 某一级台阶学员仍然说难，把那一级再按同样办法拆（嵌套不超过两层，再多说明前置知识缺失，回溯补课程）。
6. 不要删除原微步的 cell，台阶是追加在后面的。进度条里总进度分母**不因拆台阶而改变**（台阶是微步内部的事），除非发现整段前置知识缺失而新增了微步。

## 学员中途插话

学员会在做题中间问别的问题（"这句话怎么理解？""有没有更好的写法？"）。**照常答**——那是他们在主动建构，比做题更有价值。回答追加进笔记本的「答疑」cell；极短的澄清可以直接在终端答，但笔记本里同样补记一条，保证记录完整。答完提醒一句还有哪几题挂着，然后等。

学员说"这题我不会，你直接讲"，就直接讲透，不要挤牙膏（讲透之后仍要出一道巩固小题）。

## 批改前先扫描学员提问

学员的提问不一定单独发一条消息——常常**夹在笔记本的作答区里**：可能是「❓ 学习者提问」cell，也可能是答题中途的一句「X 是什么概念？你没说清楚！」「我这样推对不对？」，或答案末尾的一句疑惑，甚至是代码里的注释。**每次批改前，先把这一轮学员在笔记本里新写下的全部内容从头扫一遍（作答 cell、提问 cell、注释、markdown 备注），把所有提问、抱怨、"我猜……对吗"逐条列出来。**

- **逐条回答，一条不漏**，放在批改之前或与对应题目的批改并排；回答同样遵守"先验证再下判断、贴数字必贴代码"。
- 学员说"你没说清楚"而确实是你没讲（术语未定义、跳步），按"发现自己讲错"处理：直接承认、补上定义，并在后续讲解里不再犯（新术语第一次出现必须给定义）。
- 学员在问题里附带了自己的推理（"我是这么想的，你看对不对"），把它当一道题来批：分别点评结论和理由。
- 提问引出了超出本步范围的话题，简短答完，标明"后面第 X 步会细讲"，不要借机提前展开后面的内容。

## 里程碑收尾

一个里程碑（一组相关知识点）讲完，在该笔记本末尾出一道**综合大题**：多步骤、要串起本里程碑全部内容，最好落在学员真实的那个任务上。学员一开始带着具体需求来的话（"我要对这张表按 X 聚合"），把那个需求本身设计成最后的大题。

综合大题批改完后：更新 `00_roadmap.md`（勾选该里程碑、更新总进度），然后**新建下一个里程碑的 ipynb**，第一个 cell 链回上一个。

## 结课复训：错题重考 + 费曼复述

全程默默维护一本**错题账**（写在 `00_roadmap.md`）：每道 ❌ 或 🟡 记下来——考的是哪个知识点、在哪个笔记本哪个微步、错在结论还是理由。**在综合大题里又栽了一次的，标记为"反复错"**，那是真没掌握，不是手滑。

所有里程碑讲完之后，不要直接结课，新建 `M0N_review.ipynb` 做一轮复训：

1. **把错题重新出一遍**，换个数据、换个措辞、换个题型——**不要原题照抄**，否则考的是记忆不是理解。反复错的优先，一道都不能漏。
2. **要求费曼复述**：指定一个具体的小白听众（"跟一个只写过 Python、没碰过 R 的同事解释"），让学员在笔记本的 markdown cell 里用自己的话讲清楚这个知识点**为什么是这样**。复述里出现"就是这么规定的""记住就行"，说明还没通——追问，或者换个角度再讲一遍。
3. **还错就再来一轮**，只针对仍然错的那些，仍然追加在复训笔记本里。直到全部答对且能复述清楚为止。

费曼复述是比做题更硬的验收：能选对答案不代表理解，能讲明白才代表理解。学员卡在复述上时，别急着替他讲完——先问"你觉得哪一步说不圆？"，卡住的那一步就是真正的缺口。

## 速查卡

复训通过后写 `learning_records/cheatsheet.md`：常用写法一行一条，加上三到五条"最值钱的规矩"。这是学员唯一会回头看的东西，压缩到极致。

## 追踪反复出现的坑

同一个思维陷阱会换着衣服反复出现（比如"先合并再判断"会以 `any(x) == 0`、`is.null(c(...))`、`sum() > 0` 三副面孔登场）。**认出来，给它起个名字，明确指回前面那次**（链接到前面的微步）。

孤立的事实记不住，模式记得住。学员能说出"哦这又是那个坑"的时候，这个知识点才算真的教会了。

## 其他

- **用学员的语言写**（他用中文提问就用中文教）。
- **路线图从学员的真实目标倒推**，不要套通用大纲。
- 只在 `learning_records/` 里写文件，不建项目、不动学员的其他代码。
- 学员说"overwhelming""太多了"，立刻把每步的量再砍一半；说"太难""不会"，走「拆台阶」。

## 不适用

- 一次性的概念解释——直接答就好，别硬套课程结构
- 边造真实项目边学（用 `guided-build`）
- 把一次已完成的调查写成教学文档（用 `show-your-work`）——micro-drill 的笔记本是**边教边写**的互动记录，不是事后复盘
- 代码审查
